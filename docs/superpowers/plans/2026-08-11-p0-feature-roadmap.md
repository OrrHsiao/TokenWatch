# TokenWatch P0 功能路线图

**日期**：2026-08-11

**状态**：执行中

**产品主线**：先让数字可信，再帮助用户定位消耗，最后提供预算控制与本地数据管理

## 目标

P0 不是并行堆叠功能，而是按“可信 → 定位 → 控制 → 提醒 → 管理”的依赖顺序逐项交付。每一项都必须完成设计确认、实施计划、代码实现、验证和路线图回写，才能开始下一项。

本路线图只定义产品顺序、范围和交付门槛；当前首项的详细方案见 [数据可信度中心详细设计](../specs/2026-08-11-data-trust-center-design.md)。代码级任务与提交拆分将在详细设计确认后另写实施计划。

## 执行规则

每个 P0 功能严格经过以下状态：

1. `待设计`：只有目标和边界，不进入编码。
2. `设计待确认`：详细设计已写入仓库，等待确认关键取舍。
3. `待实施`：设计已确认，实施计划已拆到测试、文件和提交。
4. `实施中`：只实现当前序号，不并行启动后续产品功能。
5. `待验收`：功能完成，等待构建、测试、UI、隐私和本地化验收。
6. `已完成`：验收通过并回写结果、已知限制和后续依赖。

共享基础设施只能在当前功能确有需要时实现，不能借机提前实现后续 P0 的产品界面。发现阻断正确性的问题时，将它纳入当前功能的前置阶段，不改变用户看到的交付顺序。

## P0-1：数据可信度中心

### 产品结果

用户进入页面后，应在 10 秒内回答四个问题：

1. 哪些 Provider 已接入，哪些未接入或失去授权？
2. 当前 Token 汇总来自本轮扫描、last-good、内存旧结果还是磁盘汇总快照？
3. 费用中有多少来自上游报告、多少由本地价格表估算、多少尚未计价？
4. 如果状态异常，下一步应该重新检查、管理文件夹，还是仅等待价格表支持？

### 顺序内的实施阶段

1. **可信口径前置修正**
   - 模型排行必须跟随“今日 / 近 7 天 / 近 30 天 / 全部”范围。
   - 当前由 `entryCount` 渲染的“会话”改为真实含义“用量记录”，实际会话统计留给 P0-2。
   - 删除按 Token 比例反推输入/输出/推理费用的伪精确展示，改为可解释的费用来源说明。
2. **诊断领域模型**
   - 建立扫描、解析、计价、时间、显示数据来源和问题代码的稳定模型。
   - 不引入无法解释的“可信度分数”。
3. **Provider 结构化诊断**
   - Claude、Codex、opencode 上送发现、读取、last-good、首次失败跳过、正常过滤、异常拒绝和去重计数。
   - 正常 cache hit 不得被误报为使用旧结果。
4. **费用来源与覆盖率**
   - 单条费用解析返回金额和来源，而不是只有 `Double`。
   - 聚合在同一遍循环中生成 Token/记录覆盖率和未计价模型明细。
5. **状态、时间与快照迁移**
   - 分开记录上次尝试、上次成功、上次完整成功和当前展示数据的生成时间。
   - 聚合快照升级并增加 pipeline revision，避免价格或算法升级后复用旧费用。
6. **独立页面与现有入口联动**
   - 新增“数据质量”侧边栏入口，页面标题为“数据可信度中心”。
   - 当前侧边栏数据源状态可进入该页并定位 Provider。
7. **隐私、本地化与发布验收**
   - 诊断不保存路径、原始日志、prompt/response、message/request/session ID。
   - 修订隐私政策，使 Bookmark、增量缓存、聚合快照、App Group Widget 快照和 StoreKit 网络边界与实现一致。
   - 新文案覆盖全部现有语言资源，并完成 VoiceOver、键盘和长文案布局验证。

### 完成门槛

- 三个 Provider 都能区分“完整扫描”“使用 last-good”“源被跳过”“整体失败但显示旧汇总”和“干净的空数据”。
- 未配置 Provider 是中性状态，不降低已配置 Provider 的总体结论。
- 未定价只降低费用结论，不降低 Token 读取结论；已进入统一 entry 的显式上游 `$0`（当前主要是 Claude）仍算已覆盖。
- 扫描失败不会把旧数据标成“刚刚成功更新”。
- App 更新 parser、聚合或内置价格后，不会因源文件未变化而复用旧费用。
- 页面与持久化诊断不包含原始内容或完整路径。
- 所有单元测试、UI 关键状态、65 语言资源校验和 macOS 构建通过。

## P0-2：会话 2.0

### 计划边界

- 从单日、固定分页升级为日期范围、关键字搜索和组合筛选。
- 支持 Provider、模型、项目、是否子代理等现有字段。
- 会话详情展示 Token 构成、模型拆分、费用来源、首次/最近活动和记录数。
- 总览的模型、项目和趋势可带筛选上下文进入会话页。
- 数据降级时，明确会话明细是否来自完整 entries；只有汇总快照时不得伪造明细。

### 不提前进入 P0-1 的内容

- 不在可信度中心实现通用会话搜索、详情抽屉或跨图表钻取。

## P0-3：预算驾驶舱

### 计划边界

- 复用现有月度预算设置，建立主 App 预算页面。
- 展示已用、剩余、时间进度、日均可用额度和月底预测。
- 分解 Provider、项目和模型的预算贡献。
- 预测必须显示费用覆盖率；未计价 Token 存在时不能给出“确定不会超支”的结论。

### 不提前进入 P0-1/P0-2 的内容

- 不实现通知，不实现多币种和团队预算，不联网拉取账单。

## P0-4：本地提醒

### 计划边界

- 月预算达到可配置阈值时提醒。
- 依据本地历史基线识别明显突增，并提供冷却与同事件去重。
- 通知点击回到预算或对应诊断上下文。
- 自动刷新关闭或数据不可信时，通知文案必须反映数据限制。

### 不提前进入前序功能的内容

- P0-1 只生成问题状态，不发送系统通知。
- P0-3 只计算预算与预测，不请求通知权限。

## P0-5：隐私与本地数据中心

### 计划边界

- 列出外部只读源、Bookmark、内存数据、JSONL 增量缓存、Provider 聚合快照、诊断快照和 Widget 用量快照。
- 支持按 Provider 断开并删除派生数据，以及全部断开/清除。
- 清除用量时保留语言、刷新频率、预算和 StoreKit 购买权益。
- 删除 App Group 用量快照并刷新 Widget timeline，避免旧数据继续显示。
- 用 Provider 级 mutation gate 或 generation token 阻止旧扫描任务在清除后重新写回。
- 永不修改或删除 Claude、Codex、opencode 的原始日志/数据库。

## 路线图维护约定

- 每完成一个阶段，在本文件更新当前状态、完成日期和验收结果。
- 详细设计中的范围变化必须先回写本路线图，再修改实施计划。
- 后序功能若发现前序契约缺口，优先以小型修复回补，不绕过既定可信度边界。
- 当前下一交付物是 P0-1 的代码级实施计划；只有详细设计确认后才创建。
