## 目标与数据口径

- 在 macOS 状态栏和左键弹出视图中同时展示 Claude、Codex。
- 首版只读本地数据：Claude 为 `.claude.json` 中的 `cachedUsageUtilization`，Codex 为 rollout 日志中的 `token_count.rate_limits`。
- 百分比和进度条统一表达“剩余”，填充越少表示剩余越少。
- 窗口包括 5 小时和一周。没有数据时显示“—”，只有来源明确报告 0% 剩余时显示 0%。
- 额度与本地 token 历史分开表达。额度来自服务端结果的本地快照，不能由 token 数或估算费用推导。

## 状态栏

采用一个 NSStatusItem，Claude 和 Codex 为同一按钮内的两个固定区域，点击任一区域展开同一弹窗。

2026-10-28 最新迭代：用户倾向合并概览，状态栏每个额度单元调整为“圆环内居中大 Agent 图标，5H / 7D 用小字号直接叠加在图标中心，右侧显示剩余百分比”。图标和周期共享同一个中心，保持大图标，不将两者拆成上下排列。同一个 Agent 的两个周期相邻，两个 Agent 之间使用更大的间距。每个圆环 12 点起顺时针填充剩余额度，右侧数字显示同一剩余百分比。

2026-10-29 调整：周期文字压在图标中心过于显眼，影响分辨 Agent 图标。详细样式改为圆环内只保留 Agent 图标，环外两行文本“剩余百分比 / 周期”，字号与行高沿用今日 token 的“数字 / 单位”（9pt 粗体 / 7pt）；简洁样式没有环外文本，周期仍叠加在图标中心。Agent 之间主要依靠圈内图标区分，分组间距与今日 token 文本到首个圆环保持一致（约 7.25pt），只比组内窗口间距略大。组合模式中仪表盘图标的可见外圈与圆环直径一致（随状态栏高度在 20–22pt 间变化），单独今日 token 模式仍使用 18pt 标准菜单栏图标。

2026-10-29 再次调整：同一 Agent 同时展示 5H、7D 时，两个圆环合并为一个同心双环（不提供“分开 / 合并”设置）：外环 5H、内环 7D，两层线宽收细到 1.5pt、层间留 1pt，各自 12 点起顺时针填充剩余额度并各自按低额度着色；圈内图标缩小到约 11pt（20pt 圆环时约 9pt）。只合并圆环，详细样式的环外文本不变：每个周期仍为“剩余百分比 / 周期”两行，5H、7D 两段从左到右排在圆环右侧，段间距沿用原窗口间距。同心环的简洁样式不在图标上叠加周期，由内外层区分。只展示一个周期时保持原单环样式。两个 Agent 均为详细样式时整体约 159pt（原并排双环约 212pt）。

圆环默认 22pt，候选范围 20–22pt，线宽约 1.75pt。图标占圆环直径约 76%（22pt 环内约 16.7pt），尽量填满内圈并与圆弧保留间隙。简洁样式周期字号约 5pt（尽量少遮挡图标，以 Retina 下可辨认为下限），直接居中覆盖图标，使用相对图标的反色字面和细描边保证可读性，不添加独立底色块；详细样式环外百分比 9pt 粗体、周期 7pt。须以原生菜单栏实际尺寸核实小号文字清晰度。图标、正常圆弧和数字使用系统单色；低额度时仅圆弧强调颜色。弹窗继续使用细横条以方便四个窗口对齐比较。

该布局预计约占 210–240pt，以原生字体和绘制实测为准。百分比按实际文本宽度紧贴所属圆环，不为 `100%` 预留空白，使各段间隔一致、整体更窄；数字使用等宽字体，宽度只在字符数变化（如 `100%`→`99%`）时改变。图标使用真实 Agent 形状，不能只靠颜色区分。

- 设置可选择“两个周期 / 5 小时 / 一周”。窗口次序固定为 5H、7D，不自动轮播或切换到更紧张窗口。
- 今日 token 保留为可选模式；额度模式默认不混入今日 token 数字，避免常驻文本过长。
- 百分比使用等宽数字，同位数变化不改变状态栏宽度；仅字符数变化时宽度随之调整。
- 悬停说明明确工具、窗口、剩余额度、重置时间、记录时间及旧数据状态。
- 右键菜单继续承载设置、刷新、打开主窗口和退出；不在左键弹窗新增完整操作列表。
- 图标悬停说明完整 Agent 名称，辅助功能说明读出 Agent、周期、剩余额度及记录状态。圈内大图标与小号周期在同一中心直接叠加，图标与圆弧保留空隙。
- 无数据时保留周期标签，使用虚线灰环和“—”；旧数据整体弱化，悬停明确说明旧记录。

## 左键弹窗：只新增订阅区

采用合并概览，新订阅区在上，原内容作为整体在下。

当前原区域基线是 `370 × 355pt`，参照 `TokenWatch/ViewControllers/StatusPopoverViewController.swift`。以下原有表现全部保留：

- 今日 token 描述文案、字体、对齐；原刷新按钮的尺寸和样式（位置已移到弹窗右上角，见下）。
- 本月、本周、今日、日均四个摘要卡片的顺序、尺寸、字体、颜色、描边、圆角和间距。
- 日历热力图的 22 列、7 行布局，格子尺寸、间距、配色、背景、描边和悬停反馈。
- 小时趋势图的尺寸、线条、填充、坐标轴、标注、背景、圆角与交互。
- 原玻璃材质、浅深色行为、加载表现，以及现有鼠标和键盘关闭行为。
- 原区域内部所有控件的相对位置和间距。

**不得为腾出空间而压缩或缩放原控件，不得重新实现一套近似的原区域。不得替换原标题，不得给原区域新增“用量概览”标题、页脚、主窗口入口、标签页或其他装饰。**

宽度继续为 370pt。高度按 `原区域 355pt + 新订阅区实际高度 + 必要连接间距` 增长，预计约 550–590pt；不通过改变原控件高度追求固定总高度。允许原区域整体下移，但它内部的相对布局和尺寸必须保持。

从上到下：

1. 新增标题“订阅剩余”，不新增第二个刷新按钮；原刷新按钮移到弹窗右上角，与标题同行垂直居中、右缘对齐内容边缘。
2. Claude 分组：工具名、独立记录时间；下方两列分别展示 5 小时和一周，每列含窗口名称、剩余百分比、4pt 横条、重置倒计时。
3. Codex 分组：与 Claude 使用相同结构、相同顺序。
4. 一条分隔线。
5. 原 `370 × 355pt` 内容整体保留：原今日描述、四个摘要、热力图和小时趋势。

不为每个额度窗口添加独立描边卡片；使用对齐、间距和一条中性分隔线组织层级。两个 Provider 共享正常颜色，用名称识别；低额度横条才使用强调色。

仅为新增区确定内边距和间距，不调整原区域自己的内边距。原刷新入口可追加本地额度读取，原按钮样式和原统计刷新行为保留。不再实施旧草案中的“额度 / 统计”分页方案。

## 状态与文案

| 状态 | 状态栏 | 弹窗 |
|---|---|---|
| 有效快照 | 剩余百分比 | 细条、倒计时、记录时间 |
| 剩余 ≤20% | 仍显示百分比 | 对应横条橙色，数值保持可读 |
| 剩余 ≤10% | 可选小提示标记 | 对应横条红色，0% 明确为额度耗尽 |
| 正剩余不足 1% | `<1%` | 不因整数舍入误写成额度耗尽 |
| 旧快照，尚未跨过重置点 | 百分比弱化并标记旧记录 | 保留最近值，标明“旧记录”和来源记录时间 |
| 已跨过重置点，无新快照 | 该窗口显示“—” | “等待新记录”，不推断为已恢复 100% |
| 未授权 | 对应工具显示“—” | 简短授权入口，另一个工具正常显示 |
| 已授权但来源未记录额度 | 对应窗口显示“—” | “尚无额度记录”；允许窗口独立缺失 |
| 暂时读取失败 | 保留最后有效快照并继续计龄 | 标记读取状态，避免整窗 loading 覆盖已有统计 |

- 状态提示按 Provider 独立，不使用一个全局“刚刚更新”掩盖其中一个来源的陈旧数据。
- 正常横条建议延续现有绿色热力图，浅深色跟随系统。原生实现使用语义颜色，不照抄预览色值。
- 旧快照阈值是产品策略，建议先统一 60 分钟；它不代表 Codex 或 Claude 的服务端有效期。
- 时间未知时显示“重置时间未知”，不假定会话开始时间或周一零点。
- 记录时间使用 Claude `fetchedAtMs` / Codex 额度事件时间；刷新按钮仅重新读取本地记录，不能把读取时刻变成快照获取时刻。
- 刷新仅检查本地记录；原刷新按钮文案和样式保持，无变化时来源记录时间不变。
- 本地历史格式与账号归属必须在数据层校验；UI 不将其他账号的额度与当前账号合并。

## 本地数据契约

### Claude

默认文件是 Home 下的 `.claude.json`，不是 `.claude/` 内的会话记录。当前机器的 Claude Code 2.1.312 已确认存在以下结构，属于需容错的内部格式：

```json
{
  "cachedUsageUtilization": {
    "fetchedAtMs": 1793170561369,
    "accountUuid": "<account-id>",
    "utilization": {
      "five_hour": { "utilization": 32, "resets_at": "2026-10-28T12:00:00Z" },
      "seven_day": { "utilization": 14, "resets_at": "2026-11-01T00:00:00Z" }
    }
  }
}
```

- `utilization` 是已用百分比，展示时换算剩余。
- `fetchedAtMs` 是来源获取时间，单位毫秒，不能替换为 App 读文件的时刻。
- `resets_at` 是 ISO 8601 字符串，也可能为 `null`。时间未知与使用率缺失分开处理。
- 仅读取目标缓存，其余配置不进入额度模型、不打印日志。处理账号切换，不能跨账号沿用最后成功值。
- App Sandbox 下，现有 `.claude/` 目录授权不包含同级 `.claude.json`，增加单文件选择与 security-scoped bookmark，不扩大为 Home 授权。
- 自定义配置目录通过用户选择的文件支持，不假设 GUI 进程继承了 shell 环境变量。

### Codex

复用已有授权的 Codex 数据目录，读取 `sessions/`、`archived_sessions/` 中 rollout JSONL 的额度事件：

```json
{
  "timestamp": "2026-10-28T07:11:16.314Z",
  "type": "event_msg",
  "payload": {
    "type": "token_count",
    "rate_limits": {
      "limit_id": "codex",
      "primary": { "used_percent": 12, "window_minutes": 300, "resets_at": 1793188826 },
      "secondary": { "used_percent": 2, "window_minutes": 10080, "resets_at": 1793775626 }
    }
  }
}
```

- `window_minutes == 300` 对应 5 小时，`10080` 对应一周；按时长识别，不永久假定 primary / secondary 的含义。
- `used_percent` 是已用百分比，`resets_at` 是 Unix 秒时间戳。
- 使用事件 `timestamp` 作为记录时间；它是观察到快照的时刻，不保证每个 token 事件都重新获取了服务端额度。
- 跨文件按事件时间选择最新有效快照，不只选文件名最新的文件；恢复的旧会话也会写入新记录。
- 按账号和 `limit_id` 隔离；不合并多个桶或账号。旧日志缺少可靠账号归属时，须明确策略而非猜测归属。
- `rate_limits`、primary、secondary 都可能缺失，窗口独立处理。
- 额度更新不依赖 `info` / token 增量存在，不因用量去重而丢掉额度更新，也不把额度更新重复计为 token 消费。
- 原 token、费用、模型和项目统计语义保持。扩展增量缓存时评估版本和迁移，避免旧缓存永久漏出额度。

两个来源都是本地快照。首版不联网，不读取 `.credentials.json`、`auth.json`、OAuth、Cookie 或 Keychain，不接入 App Server。非有限数值、损坏字段、追加中的半行须局部容错，不把缺失或失败转成 `0%` / `100%`。
